## Phase 3: engine architecture

Arclight is now an editor for building scenes. Models become GameObjects with components in a Hierarchy, are selected by clicking in the Scene view and moved with gizmos, and the scene is saved to a file and opened again next time. Under the hood, draws are sorted and culled, models switch to simpler levels of detail in the distance, files are reached through a virtual file system, and imported assets are cooked into binary formats that load in a fraction of the import time.

### What's in it
- **Scenes of GameObjects and components**: a transform hierarchy with Hierarchy and Inspector panels. Reparent and reorder by drag and drop, duplicate (Ctrl+D), delete, rename, and add components. Imported glTF files keep their node hierarchy.
- **Picking and gizmos**: click an object in the Scene view to select it, with an outline around it. W / E / R move, rotate and scale it in world or local space, with optional snapping.
- **Scene and prefab files**: *File > New / Open / Save / Save As* (Ctrl+N, O, S, Shift+S; Cmd on macOS). You are asked to save unsaved changes before they are lost, the title bar shows a `*` while there are some, and the last scene opens again at start-up. Right-click an object and choose *Save as Prefab* to place copies of it later. Anything changed while playing (F5) is undone on Stop.
- **Asset pipeline**: each asset gets a `.meta` file with a stable id and its import settings (scale and levels of detail for models; colour space, mip maps and maximum size for textures). Imports are cooked into `.arcmodel` and `.arctex` files and only redone when the source or the settings change. The sample Lantern loads in about 90 ms instead of 0.9 s.
- **Files panel**: browse every mount, see each asset's state and settings, reimport, and drag models and prefabs into the Scene view. Native open and save dialogs on both platforms.
- **Culling and levels of detail**: objects outside the camera's view are skipped a whole subtree at a time, and models switch between simplified versions when the difference is under a pixel. *View > Visibility* can freeze culling so you can fly away and look at it.
- **Skybox**: a procedural sky, or one loaded from a folder of six images (`px`, `nx`, `py`, `ny`, `pz`, `nz`).
- **Render list**: draws sorted by pipeline, buffers and material to avoid state changes, and blended surfaces back to front, from a shared pool of geometry buffers. *View > Rendering stats* shows the counts.

Full list: [CHANGELOG.md](https://github.com/Anand-Ramnarain-27/arclight-engine/blob/v0.4.0/CHANGELOG.md)

### Downloads
| File | Platform |
|---|---|
| `Arclight-0.4.0-windows-x64.zip` | Windows 10/11, x64, a GPU with Direct3D 12 |
| `Arclight-0.4.0-macos-arm64.zip` | macOS 14+ on Apple silicon |

**Windows:** extract the zip and run `Arclight.exe`. Keep the `Shaders` and `Assets` folders next to it. The build is unsigned, so SmartScreen may warn you. Choose *More info > Run anyway*.

**macOS:** the build is unsigned and not notarized, so macOS blocks it after download. Extract the zip, then in Terminal:
```
cd ~/Downloads/Arclight-0.4.0-macos-arm64
xattr -dr com.apple.quarantine .
./Arclight
```

Cooked assets and your settings are kept in the per-user folder (`%APPDATA%\Arclight\Editor` on Windows, `~/Library/Application Support/Arclight/Editor` on macOS). The first start cooks the sample model, which takes about a second.

### Editor controls
**Scene panel** (pointer over the scene): left click to select · W / E / R move / rotate / scale gizmo · Ctrl while dragging to toggle snapping · right drag to look · W A S D / Q E to fly · Shift for 4x speed · Alt + left drag to orbit · middle drag to pan · wheel to dolly · F to frame the selection.

**Everywhere:** Ctrl+N / O / S / Shift+S new, open, save, save as · Delete · Ctrl+D duplicate · F5 play/pause · Shift+F5 stop · F6 step one frame · +/- time scale · 0 reset time scale · F11 capture a GPU frame (when a capture tool is attached) · View > Reset Layout restores the default docking layout. On macOS, Cmd replaces Ctrl.

### Building from source
```
cmake --workflow --preset windows-release   # or macos-release
```
macOS builds also need the [Vulkan SDK](https://vulkan.lunarg.com/sdk/home#mac), which provides DXC. Configuring downloads the dependencies and the sample model, so it needs an internet connection. See the README for IDE setup.
